# Prophecy viewer

The frontend is a dependency-free static application synchronised to `video.currentTime`. It renders prediction cards over the recorded match, tracks answers in browser memory and displays an illustrative session score, streak, rewards and final leaderboard.

## Run locally

Serve the repository root so the app can reach both the viewer assets and generated backend payload:

```powershell
python -m http.server 8000
```

Open `http://localhost:8000/app/`.

The match video is streamed from the repository's `DemoVideo` GitHub Release.

## Active question source

`app/app.js` loads:

```text
../data/out/questions.json
```

The query suffix in the fetch URL is only a cache buster. The active source is the schema-v5, seven-question payload generated by `pipeline/run.py`.

`app/questions.json` is an older schema-v2 six-card reference. It is marked `legacy_unused` and is not loaded by the current viewer.

## Card lifecycle

The viewer uses these schema-v5 timestamps:

```text
show_at_s
  -> close_at_s          answer entry closes
  -> window_end_s        prediction contract reaches its boundary
  -> resolve_at_s        verified result or void is shown and scored
  -> result_hide_at_s    result leaves the video overlay
```

`collapse_at_s` is present in the backend payload but is not yet rendered as a distinct compact pending state.

## Question fields

The renderer consumes the schema-v5 envelope's `questions` array. Important fields include:

- `id`, `contract` and `selection_method` for identity and provenance;
- `headline`, `context` and `text` for card content;
- `options` and `correct_option_id` for interaction and settlement;
- lifecycle timestamps for video synchronisation;
- `status` and optional void metadata;
- `result_headline`, `result_detail` and `result_consequence`; and
- `points` for the local session score.

Options are dynamic, so binary, three-squad and four-squad questions share the same renderer. Scoring occurs only at `resolve_at_s`. Session state is not persisted and resets when the page reloads.

The backend does not provide an outcome probability or measured fan pulse. The result card's crowd-correct percentage is deterministic illustrative UI content, not real audience data.
